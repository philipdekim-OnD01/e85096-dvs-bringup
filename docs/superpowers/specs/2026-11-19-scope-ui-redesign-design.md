# 현미경 뷰어 화면 재구성 설계 (2026-11-19)

## 목적

사용자 평가: "ui/ux가 직관적이지 못 해 불편해, 상용제품처럼 멋지게 만들어줘 시장조사좀 해서".

상용 제품을 조사했다(CytoSMART Omni/Lux3, Incucyte, CELLCYTE X, EVOS, Countess 3, ZEISS Labscope). 공통점은 다섯 가지다.
1. 실험 단위의 단계별 흐름이 있다.
2. 분석은 이름 붙은 모듈(프리셋)로 고른다.
3. 크기 조건은 분포 그래프 위에서 정한다.
4. 결과는 추세 그래프와 시점별 사진을 함께 보여 준다.
5. 폰·태블릿으로 원격 확인한다.

지금 화면의 문제는 세 가지다.
- 옆 칸 하나에 개발용 기능(레지스터, LLP/FLL)과 사용자 기능이 섞여 있다.
- 분석 조건을 숫자로만 넣는다. 그래서 최소 5 µm 설정으로 실제 시료에서 0개가 기록돼도 화면에서 알 수 없었다.
- "실험"이라는 단위가 보이지 않는다.

## 대상 (사용자 승인, 2026-11-19)

- 연구자가 PC 브라우저로 실험을 설정하고 결과를 본다.
- 폰은 며칠 걸리는 실험의 진행을 확인하는 데 쓴다.
- PC에서는 정보를 촘촘히 담은 대시보드, 폰에서는 같은 화면이 한 줄 카드로 접힌다.
- 시연용 화면은 따로 만들지 않는다.

## 방식 (고른 것: 1)

1. **(고름) `scope.html`을 그 자리에서 재구성한다.**
   - 실시간 영상 엔진(프레임 받기, 표시 LUT, 확대·이동, 측정, 히스토그램)과 기록 그래프 코드는 그대로 쓴다.
   - DOM, CSS, 흐름만 바꾼다.
2. 새 페이지를 만들고 지금 페이지는 고급용으로 남긴다. 영상 엔진이 두 벌이 되어 고르지 않았다.
3. UI 프레임워크를 들인다. CDN을 쓸 수 없어(오프라인 실험실) 파일을 보드에 넣어야 하고, 얻는 것에 비해 무겁다. 고르지 않았다.

## 화면

머리줄: 상표 | 탭 [실시간] [실험] [결과] | 상태(LIVE·fps, REC n/전체·다음 촬영) | ◉ 촬영 | ⚙ 고급

폰 폭(≤ 900 px)에서는 탭이 아래 탐색 막대로 내려간다.

### 실시간

- 큰 영상과 확대 도구는 지금과 같다.
- 오른쪽 칸에는 카드를 둔다.
  - 조명·노출: LED, 노출 막대, 자동 노출, 평균 장수
  - 물체 표시: 켜기, 분석 프리셋, 개수와 평균 지름
  - 표시 보정(접힘): 밝기, 대비, 감마, 자동 대비, 반전, 십자선
  - 측정
  - 시료 이름과 최근 사진
- **물체 표시를 켜면:**
  - 약 1.5초마다 지금 프레임을 분석한다(`/analyze/preview?fmt=json`).
  - 물체를 등가 지름의 원으로 영상 위에 그린다. 원은 영상 좌표에 있어서 확대해도 맞는다.
  - 영상 왼쪽 위에 "물체 N개 · 평균 d µm"를 보인다.
- **실험 중:** 실시간 프리셋을 바꿀 수 없다. 바꾸면 진행 중인 실험의 분석 조건이 바뀌기 때문이다(`save_photo`는 찍는 순간의 cfg를 쓴다).

### 실험

**진행 중인 실험이 있을 때**는 상태 카드를 보인다.
- 시료, 시작 시각, 진행 막대(n / 전체), 다음 촬영까지 남은 시간, 경고
- [결과 보기], [실험 끝내기](확인 창을 띄운다)
- 새 실험은 막는다.

**없을 때**는 4단계 마법사를 보인다. 왼쪽에 단계 목록을 두고, 오른쪽에 단계 내용을 둔다. 마법사 값은 브라우저의 초안에만 두고, 시작할 때 `/set`으로 보낸다.
1. **시료:** 이름(80자)과 메모(80자).
2. **무엇을 셀까:**
   - 프리셋 카드 [입자·먼지] [세포] [콜로니] [직접 설정]
   - 어두운/밝은 물체, 민감도 1~5, 붙은 물체 나누기, 개별 물체 추적
   - **최소 크기 비교:** 지금 프레임을 최소 크기 6가지(5, 10, 20, 50, 100, 200 µm, 최대는 그대로)로 분석한다. 결과는 원을 그린 작은 그림 6장과 각 개수로 나란히 보인다. 하나를 누르면 그 최소 크기로 정해진다.
   - 분석은 고른 최소 크기부터 하고, 비교 그림은 하나씩 채운다. 최소 크기만 바꾸면 이미 센 결과를 다시 쓴다. 보드4에서 잰 시간은 최소 5~20 µm가 0.3~0.4초, 50 µm가 0.8초, 100 µm가 1.9초, 200 µm가 3.8초다. 흐림 필터가 최소 크기에 비례해 커지기 때문이다. 6가지를 한 번에 하면 7.6초가 걸렸다.
   - 큰 미리보기에는 고른 조건의 원을 그린다.
   - 크기 분포 막대에는 최소·최대 손잡이가 있다. 끌어서 범위를 정하면 다시 분석한다. 숫자 칸도 함께 둔다.
3. **일정과 기록:**
   - 간격 [10초 시험 … 6시간], 기간 [1시간 … 30일, 멈출 때까지]
   - 촬영 전: LED, 자동 노출, 평탄화(기준 영상이 없으면 그렇다고 알린다), 4장 평균
   - 기록: 원본 PNG, 윤곽 사진, 보관 한도
   - 예상 장수·용량과 남은 공간("5분마다 3일 → 865장 · 약 1.1 GB · 남은 공간 38 GB")
4. **확인:** 고른 것을 모두 요약하고 [실험 시작]을 둔다. 시작하면 결과 탭으로 간다.

### 결과

지금의 전체 화면 기록 패널을 탭으로 옮긴다.
- **위:** 실험 선택, 핵심 수치 타일 4개, 계열 칩, [CSV 사진별] [CSV 물체별] [PDF 보고서]
  - 핵심 수치: 최근 개수와 직전 대비 증감, 평균 지름, 사진 수(진행 중이면 n / 전체), 다음 촬영
- **본문:** 그래프(공통 시간축, 측정값마다 하나. 지금 코드 그대로) + 오른쪽 사진 보기(윤곽/원본 전환, 값 표, 크기 분포)
- **아래:** 사진 띠(썸네일, 선택과 연동)와 ▶ 타임랩스 재생. 다음 사진이 다 읽힌 뒤 넘어간다.
- **PDF 보고서:** `window.print()`로 인쇄 화면을 연다.
  - 인쇄할 때는 밝은 색으로 바꾸고 그래프를 다시 그린다.
  - 인쇄 화면에만 나오는 머리말: 실험 번호, 시료, 기간, 분석 조건

### ⚙ 고급 (오른쪽 서랍)

- 평탄화 기준 찍기·보정 켜기
- 히스토그램
- 센서 레지스터·상태
- 화소 크기(µm)
- 단축키 안내
- OpenCV 상태

## 프리셋 (내 판단, 시작값)

| 프리셋 | 대상 | 크기 µm | 민감도 | 나누기 | 추적 |
|---|---|---|---|---|---|
| 입자·먼지 | 어두운 | 20 ~ 1000 | 3 | 켬 | 끔 |
| 세포 | 어두운 | 8 ~ 80 | 4 | 켬 | 끔 |
| 콜로니 | 어두운 | 100 ~ 5000 | 3 | 켬 | 켬 |
| 직접 설정 | 지금 값 | | | | |

- 입자·먼지 값은 실물 프레임에서 정했다. 20~500 µm, 민감도 3에서 8개를 찾았고, 눈으로 본 것과 맞았다(11.70).
- 세포와 콜로니 값은 실물로 확인하지 않은 시작값이다.
- 화소 크기 2.24 µm는 아직 확인하지 않았다.

## 바꾼 것: "자동 맞춤" 대신 "최소 크기 비교"

앞 메시지에서는 "지금 화면으로 자동 맞춤"을 제안했다. 하지만 실물 프레임에서 최소 크기에 따른 개수가 한 방향으로 움직이지 않았다(5 µm → 0, 10 → 1, 20 → 7, 30 → 11).
- 이유: 최소 크기가 흐림 정도를 정하기 때문이다.
- 그래서 분포의 골짜기를 찾는 식의 자동 기준은 믿을 수 없다.
- 대신 6가지 결과를 나란히 보이고 사용자가 눈으로 고르게 했다. 카메라의 노출 브래킷과 같은 방식이다.

## 서버 변경 (작게)

- `/analyze/preview`
  - 선택 인자 `dark`, `min`, `max`, `sens`, `split`을 받는다. 범위 자르기는 `/set`과 같고, cfg는 바꾸지 않는다.
  - `fmt=json`이면 `{count, mean_d_um, total_area_um2, truncated, objs: [[x, y, d_um], …]}`를 돌려준다. objs는 큰 것부터 3000개까지다.
  - 인자가 없으면 지금처럼 JPEG를 돌려준다.
- `/stat`에 `disk: {free_gb, photos_gb, n}`을 더한다. 사진 폴더 크기 검사는 `disk_full`과 같은 함수를 쓰고, 결과는 30초 동안 캐시한다.

## 하지 않는 것

- MP4 내보내기(다음 판)
- 밝은 화면 테마(인쇄만 밝게)
- 새 라이브러리
- 사진 삭제 기능

## 실패로 보는 것

- 실시간 영상, 수동 촬영, 진행 중인 자동 촬영이 지금보다 나빠지는 경우
- 개발 기능(레지스터, 평탄화)을 쓸 수 없게 되는 경우
- 폰 폭에서 화면이 가로로 넘치는 경우

## 시험

1. Mac에서 `--fake`(실제 프레임으로 만든 YUYV)를 포트 8091로 띄운다. 헤드리스 Chrome(CDP)으로 다음을 확인한다.
   - JS 오류가 없다.
   - 탭 전환, 마법사 4단계와 실험 시작, 결과 탭, 재생, 인쇄 화면, 폰 폭을 스크린숏으로 확인한다.
2. 보드4의 8091에서 같은 시험을 한다(보드 numpy 1.24, 분석 시간).
3. 사용자가 시안을 눌러 본다. 고칠 것을 반영한 뒤 사용자가 sudo로 `install.sh`를 실행한다.
4. 설치 뒤 진행 중인 실험 #1이 이어지는지 확인한다.
