# 현미경 자동 촬영 · 물체 분석 · 기록(DB) 설계 (2026-11-19)

## 목적

보드4의 SOL 현미경(`tools/board/scope/`)이 정해진 간격으로 사진을 찍는다. 사진마다 보이는 물체의 개수와 크기를 재서 DB에 남긴다. 날짜·시간별 추세 그래프를 사진과 함께 본다. 대상(세포, 입자 등)을 정해 두지 않는 일반 제품 형태로 만들고, 조건은 체크박스로 고른다(사용자, 2026-11-19).

## 목표 / 하지 않는 것

- 목표:
  - 자동 촬영(간격, 끝나는 때)
  - 촬영 전 처리(LED, 자동 노출, 평탄화, 4장 평균)
  - 분석(어두운/밝은 물체, 크기 범위 µm, 민감도 1~5, 붙은 물체 나누기, 개별 물체 추적)
  - 기록(원본 PNG, 윤곽 표시 사진, 보관 한도)
  - 그래프(개수, 평균 크기, 총면적, 크기 분포, 개별 물체 크기)
  - CSV 내보내기
- 하지 않는 것:
  - 물체 종류 구별(AI 검출, YOLO). 필요해지면 분석 방법 옵션으로 덧붙인다.
  - 오래된 사진 자동 삭제. 보관 한도에 닿으면 자동 촬영을 멈추고 알린다. 데이터를 지우지 않는다.
- 실패로 보는 것:
  - 자동 촬영이 실시간 화면이나 수동 촬영을 망가뜨리는 경우
  - OpenCV가 없을 때 뷰어가 아예 뜨지 않는 경우. 이때는 분석만 꺼져야 한다.

## 방식 (고른 것: 1)

1. **(고름) OpenCV 고전 영상처리. `opencv-python-headless` wheel을 `/opt/e850-scope/py`에 푼다.**
   - wheel은 4.11.0.86 aarch64판 하나(29.5 MB)이고, 보드의 numpy 1.24를 그대로 쓴다.
   - 시스템 패키지는 건드리지 않는다.
2. Debian `python3-opencv`: 패키지 344개가 따라오고 시스템 라이브러리가 올라간다. 고르지 않았다.
3. numpy만 쓰는 구현: 설치는 필요 없다. 그러나 느리고, 붙은 물체 나누기(watershed)를 직접 짜야 한다. 고르지 않았다.

분석 순서(구현하면서 실물 영상에 맞게 바꾼 최종판, 근거는 BOOT 문서 11.70):
1. 배경은 1/8 영상의 중앙값이다. 창은 최대 물체의 2배이고, 테두리는 점대칭으로 덧댄다.
2. 흐림: σ = 최소 지름/4.
3. 대비: (배경 − 영상)/√배경.
4. 임계값: 중앙값 + k·MAD. k는 민감도에 따라 정한다.
5. 경계: 물체마다 대비 최댓값의 절반에서 자른다.
6. 열림·닫힘을 하고 구멍을 메운다.
7. (선택) 붙은 물체: 거리 지도에서 최댓값의 0.7을 넘는 core가 둘 이상이면, 화소를 가장 가까운 core에 나눈다. watershed는 평평한 거리 지도에서 고르지 않게 나눠서 쓰지 않았다.
8. 연결 성분의 등가 지름을 µm 범위로 거른다.

ImageJ "Analyze Particles"와 같은 방식이고, 학습 데이터가 필요 없다.

## 구조

- `scope_rec.py`(새 파일):
  - `analyze(img, pixel_um, dark, min_um, max_um, split, k_mad)`
  - SQLite(`/var/lib/e850-scope/scope.db`)
  - 추적(직전 사진 물체와 가까운 순서로 1:1 짝짓기, 거리 ≤ max(지름, 10 px))
  - 윤곽 그림
  - CSV
  - 합성 원판 영상으로 스스로 확인하는 시험(`python3 scope_rec.py --selftest`)
- `scope.py`:
  - 자동 촬영 스레드
  - 서버 쪽 자동 노출(평균 118 목표, 브라우저와 같은 규칙)
  - 새 raw 프레임 N장 평균
  - HTTP 경로: `/rec/runs`, `/rec/photos?run=`, `/rec/objects?photo=`, `/rec/csv`, `/analyze/preview`
  - `/capture`도 분석해서 DB에 넣는다(수동 촬영 = run 없음).
  - cv2가 없으면 분석만 끄고 나머지는 그대로 동작한다.
- `scope.html`:
  - 옆 칸에 "자동 촬영 · 분석" 묶음(체크박스, 선택 상자, "분석 미리보기")
  - 머리줄에 "기록" 버튼. 누르면 전체 화면 기록 패널이 뜬다: 실행(run) 선택, 계열 체크박스, 공통 시간축의 작은 그래프 여러 개, 점을 누르면 그 사진과 윤곽, 크기 분포 막대, CSV 링크.
  - 그래프는 canvas로 직접 그린다. 실험실이 오프라인일 수 있어 CDN을 쓰지 않는다.
- `install.sh`: `scope_rec.py`를 복사하고, wheel이 있으면 `py/`에 푼다.
- DB 표:
  - `runs(id, started, ended, sample, every_s, opts)`
  - `photos(id, run_id, name, t, time, exp, led, pixel_um, mean, count, mean_d_um, total_area_um2, opts)`
  - `objects(photo_id, x, y, area_um2, d_um, track)`
- 설정(`settings.json`의 cfg)에 넣는 키:
  - 자동 촬영: `tl_on`, `tl_every`, `tl_hours`, `tl_start`, `tl_run`
  - 촬영 전: `tl_led`, `tl_ae`, `tl_flat`, `tl_avg4`
  - 분석: `an_dark`, `an_min_um`, `an_max_um`, `an_split`, `an_track`, `an_sens`
  - 기록: `rec_png`, `rec_ov`, `rec_gb`
- 자동 촬영 한 번의 순서:
  1. (LED) 255로 켜고 새 프레임 3장을 기다린다.
  2. (자동 노출)
  3. 새 raw 프레임 1장 또는 4장을 평균한다. (평탄화) 기준 영상 이득을 곱한다.
  4. 저장하고 분석하고 DB에 넣는다.
  5. LED와 노출을 촬영 전 값으로 되돌린다.
- 서비스가 다시 시작되어도 같은 run을 이어 간다. 끝나는 때가 지나면 run을 닫는다.

## 정한 것 (근거)

- **민감도 옵션(1~5, 기본 3):** 설계 스케치에는 없었다. 실물 시료에는 질감이 있어서 검은 입자의 대비가 질감 잡음의 3.4~5.9배밖에 되지 않았다. 고정 기준(5 MAD)으로는 거의 찾지 못해서 넣었다.
- **개수 상한:** 개수는 전부 세고, 물체 기록과 윤곽은 큰 것부터 5000개까지만 한다(`truncated`).

- **보관 한도:** 사진 폴더 크기가 한도를 넘거나 여유 공간이 2 GB 아래로 내려가면 자동 촬영을 멈춘다. 데이터를 잃지 않으려는 것이다.
- **윤곽 사진:** JPEG(`.ov.jpg`)로 둔다. 컬러 PNG는 원본의 약 3배 크기다.
- **화소 크기:** 기존 설정 `pixel_um`(2.24, 아직 확인 필요)을 그대로 쓴다. 물체 크기와 함께 사진마다 기록한다.
- **가장자리에 걸린 물체:** 빼지 않는다(요청 없음). 크기 통계가 조금 작게 나올 수 있다.

## 시험

- 합성 영상 self-test: 개수, 지름, 붙은 두 원판 나누기, 추적 ID 유지
- 보드4에서 `--fake`로 다른 포트에 띄운다(실제 사진에서 만든 YUYV 사용). 같은 포트를 쓰는 서비스는 건드리지 않는다.
- 설치 뒤 실제 키트로 짧은 간격(30초) 자동 촬영을 해서 DB와 그래프를 확인한다.
