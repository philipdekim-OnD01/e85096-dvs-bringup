01 · 부팅 구조

LK → boot.img → initramfs → Debian

LK
Android 10 부트로더→boot.img v2
Image + initramfs + DTB→/init (busybox)
1단계 모듈 순서대로 insmod→switch_root
root=PARTLABEL=userdata→Debian 12
systemd

왜 initramfs가 꼭 필요한가

eMMC(dw_mmc), 타이머(exynos_mct), 핀 제어, 클록, PMIC(s2mpu12)가 모두 모듈이다. 커널만으로는 루트 파일시스템을 읽지 못한다. Android에서 vendor_boot가 하던 일을 busybox init이 한다.

DTB 하나로 합치기

SoC dtb와 ERD3830 overlay를 미리 합친다(fdtoverlay). /chosen bootargs를 리눅스용으로 바꾸고, CPU reg를 이 보드 BL31 방식(cluster<<8 | core)으로 고친다.

명령줄 핵심

cpuidle.off=1 (C2에서 코어가 안 깨어남)
clocksource=arch_sys_counter
panic=0, loglevel=8
cgroup_disable=cpu (데스크톱 보드)

docker run --rm -v e850-out:/o:ro -v "$PWD/tools/linux510:/t:ro" -v <out>:/out -v <Android10 백업>:/b:ro \
    ubuntu:22.04 sh /t/build-bootimg.sh root=PARTLABEL=userdata        # → boot.img, cmdline.txt, merged.dtb

02 · 작업 방식

복구 수단을 먼저 만들고, 사람 없이 원인을 좁힌다

복구 수단

  • UART(115200)는 커널 로그 전용. Mac이 uartlog.py로 계속 기록한다
  • USB ACM 콘솔: root 자동 로그인. 명령은 acm.py로 보낸다
  • 워치독: 멈추면 리셋 → LK가 Abnormal RST_STAT로 fastboot에 들어간다 → 알려진 정상 이미지를 다시 굽는다
  • to-fastboot: 워치독 데몬을 죽여 버튼 없이 fastboot로
  • fbmini: LK가 모르는 getvar에서 멈추는 것을 피한 작은 fastboot 클라이언트. userdata는 700 MB 조각으로 굽는다

원인 좁히기

  • cycle.sh: 빌드 → 굽기 → 재부팅 → UART로 판정. 사람 손 없이 이분 탐색
  • 시험용 커널 인자: e850.nousb, e850.stage2=N(2단계 모듈 앞 N개만), e850.noswitch(루트로 안 넘어감)
  • 기록 원칙: 관찰, 가설, 실패한 실험, 보드에 바꾼 것을 나눠 적는다. 재지 않은 것은 됐다고 쓰지 않는다
  • 위험한 실험(idle, PMU, 부트 인자)은 USB와 UART를 꽂고, 복구 방법을 먼저 준비한 뒤에 한다

LK의 fastboot boot(RAM 부팅)은 이 보드에서 fb: boot를 찍고 멈춘다. 전원을 다시 넣어야 하므로 쓰지 않는다(7.3, 11.80).

04 · 부팅

"UART를 열면 멈춤"의 진짜 원인: 첫 CPU idle

UART를 열 때, 가젯을 켤 때, 루트를 마운트할 때 멈추는 것이 모두 같은 현상이었다. 워치독을 켜 멈춤을 리셋으로 바꾸고, 커널 인자를 바꿔 가며 이분 탐색했다.

커널 인자 (공통: e850.nousb e850.noswitch)결과
2단계 모듈 전부모듈 91개 적재 직후 리셋 (11.6 s)
e850.stage2=06.2 s에 리셋 (루트 마운트는 성공)
e850.stage2=0 e850.nowdt리셋 없이 멈춤 → 워치독은 원인 아님
e850.stage2=0 cpuidle.off=160초 이상 생존

해석

init이 일을 마치고 CPU가 처음 idle에 들어가는 순간 멈췄다. 모듈을 적재하는 동안에는 CPU가 바빠서 버텼다. Android에서는 exynos-cpupm 등이 idle 상태와 웨이크업을 먼저 설정해 둔다.

지금도 cpuidle.off=1로 둔다(전력은 늘어남). 빼 보는 시험(11.12)은 부팅 초반에 멈춰 실패했다.

04 · USB 가젯과 HDMI

없는 칩을 기다리는 드라이버, 덮어쓴 패널 ID

USB 가젯: e850-vbus.ko

DT는 ERD3830용이라 케이블 연결(VBUS)을 S2MU106 PDIC → usb_notifier로 받는다. E850-96에는 이 칩이 없어 DWC3가 클록이 꺼진 채 남았다.

작은 모듈이 dwc3_exynos_vbus_event(dev, true)를 한 번 부른다. init은 UDC가 configured가 될 때까지 기다린 뒤 ttyGS0을 쓴다. 나중에 gadget이 준비될 때까지 기다리게 고쳤다(11.32).

HDMI: DECON → DSIM → LT8912B

HDMI는 SoC MIPI-DSI를 Lontium LT8912B 브리지가 바꾼다. 값은 Android 10의 DTB·DTBO에서 꺼냈다(1920×1080@60, 4 lanes).

04 · 카메라

OV5647: vendor ISP(fimc-is)를 우회해 RAW를 받기

  • Pablo(fimc-is)는 ISP 체인 전체를 전제로 한다. 센서 그룹만 돌리도록 bypass 패치를 넣었다(modules/ov5647-pablo/bypass.sh).
  • 순서: S_INPUT → S_FMT → REQBUFS → QBUF → STREAMON. 센서 모드는 V4L2_CID_IS_S_SENSOR_SIZE로 고른다.
  • RAW(VC0)는 leader가 아니라 VC 캡처 노드(/dev/video214)로 DMA된다. 메타의 구조체 위치는 fimc-is.ko DWARF에서 읽었다.
  • CSIS가 RAW10을 화소당 16비트로 써서 SysMMU fault → dma-buf를 2배로 잡는다.
  • 스트림 시작 멈춤, 프레임마다 쏟아지는 로그도 패치로 고쳤다(9.9, 11.32).

640×480 RAW10, 2레인 275 Mbps. 8코어에서 HDMI 실시간 영상까지 냈다. 이 경로가 뒤의 DVS 센서 작업의 바탕이 됐다.

05 · Wi-Fi

칩 안의 무선랜: 펌웨어 꺼내기부터 패닉 원인까지

올리기

  • Android 백업의 super에서 vendor ext4를 꺼내 /etc/wifi(mx140.bin 등)를 얻었다. LP 메타데이터 파서는 30줄(lpunpack-min.py)

펌웨어 패닉

  • 몇 시간마다 WLBT FW PANIC. 기본값은 복구 안 함 → disable_recovery_handling=0을 패닉 전에 써서 자동 복구(재연결 5.6~6.5 s)
  • vendor에 있던 기호표로 패닉 기록을 풀었다: 펌웨어 힙 할당기의 Data Abort
  • Linaro Android 13 판 펌웨어로 교체. 옛 2019년 판은 약 3.8시간마다 났다

vendor 버그 2개

  • 오류 기록 버퍼 크기를 두 번 빼서 음수 → vsnprintf WARN. 고침
  • /proc/.../mx_panic이 0666: 아무 사용자나 읽기만 해도 펌웨어 패닉 → 0600
  • BT를 켠 채 쓰려면 고친 scsc_wlan이 필요(11.78)
패닉이 나도 6초 안에 다시 붙는다. 복구 횟수는 /proc/driver/mxman_ctrl0/mx_recovery_count로 본다.

05 · CPU 8코어

코어가 하나만 켜지던 이유: 타이머와 MPIDR

1) CPU1 lockup의 원인은 MCT 타이머

MCT 로컬 타이머 인터럽트가 CPU1까지 오지 않아 tick을 못 받았다. exynos_mct를 빼고 코어마다 PPI로 받는 ARM arch timer만 쓰자 CPU1이 살았다(clocksource=arch_sys_counter).

3) hotplug: modules/e850-cpuhp

Linaro의 Exynos850 hotplug 패치 방식대로, 켜기 준비(PMU wake-up 마스크 해제)를 CPU_ON 전에 부팅 CPU에서 한다. vendor는 새 코어가 이미 돈 뒤에 해서 코어가 그 전 단계를 못 넘었다.

2) BL31은 MPIDR을 cluster<<8 | core로 읽는다

CPU1CPU2CPU4CPU7
vendor 5.10 DT0x1000x2000x100000x10300
Android 10 DT0x10x20x1000x103

5.10 값 0x100은 클러스터1 코어0을 깨워 CPU1처럼 보였고, 0x200부터는 없는 클러스터였다. build-bootimg.sh가 merged.dtb의 reg를 Android 10 값으로 바꾼다 → 8코어 동작, 1시간 부하 시험 통과.

05 · DVS 센서

CN4 MIPI로 DVS(S5KRC1S) 이벤트 받기

IRQ 폭주

3초에 ISR 238,427번, 거의 전부 VRESOL_MISMATCH. CSIS 드라이버가 VC별 오류 상태를 읽기만 하고 지우지 않았다. kretprobe 모듈(csis-irqstat)로 센 뒤 고쳤다.

CRC 오류

초당 약 8,700개, 거의 모든 줄이 깨졌다. 레인 속도·settle이 아니라 센서 D-PHY PLL 배수가 원인이었다. 값을 바꾸자 CRC 0. 다른 보드는 케이블을 다시 꽂아 해결했다(11.53).

결과

CN4 2레인으로 약 40 MB/s, MIPI 38.5 프레임/s를 장시간 DRAM에 받는다. C 디코더(libdvsview.so)로 HDMI 30 fps, 웹 페이지로 설정과 통계를 본다.

06 · 기능 묶음

features/: 드라이버 + 펌웨어 + 설정 + 서비스를 한 묶음으로

기본 이미지에는 Wi-Fi와 HDMI 콘솔만 있다. 다른 기능은 보드마다 골라 넣고 뺀다.

# 보드에서
e850-feature list
e850-feature install ethernet audio video bt usbhost desktop
e850-feature remove desktop

# Mac에서: 모듈 빌드·strip, 펌웨어 받기, 묶기, 보내기
sh features/host/bundle.sh
sh features/host/deploy.sh philip@<IP> audio bt

구조

  • 기능마다 디렉터리 하나: usbhost ethernet audio video bt desktop. feature.sh가 install / remove / status
  • 첫 줄 주석 # about:, # needs:(의존 기능)
  • 모듈은 /lib/modules/$(uname -r)/extra/ (depmod search extra built-in로 vendor 판보다 먼저)
  • 펌웨어는 Linaro 고정 커밋에서 받아 sha256 확인. git에는 넣지 않는다

06 · 오디오 · BT · 유선랜 · MFC

vendor 코드의 숨은 가정들

기능증상원인해결
오디오"Calliope is ready" 뒤 카드 등록 실패machine 드라이버가 DT 자식을 위치로 대응. fdtoverlay가 자식 순서를 거꾸로 넣음이름으로 정렬해 대응하는 패치
Bluetooth커널 BlueZ 연결부가 빌드 안 됨wakelock.h 없음, module_init 두 번, 커널 버퍼를 fops에 넘김사용자 공간 브리지: /dev/scsc_h4_0 ↔ /dev/vhci
BT + Wi-FiBT를 켠 뒤 Wi-Fi 패닉에서 복구 실패WLBT 복구 경로가 BT 서비스를 못 다룸고친 scsc_wlan을 bt 기능이 함께 넣음
유선랜부팅마다 MAC가 바뀜LAN9514에 EEPROM 없음, 허브 뒤라 호스트 모드에서만 보임smsc95xx 외부 모듈 + .link로 MAC 고정
MFC부팅 23 s에 커널 패닉장치 등록 뒤 drvdata를 넣기 전에 udev가 열면 0을 돌려줌!dev이면 -ENODEV (한 줄)

함정: 카드 등록이 실패한 같은 부팅에서 오디오 모듈을 다시 올리거나, scsc_wlan을 rmmod 뒤 다시 올리면 커널이 죽는다. 바꾼 모듈은 재부팅해서 쓴다. MFC는 열려 있을 때 rmmod하면 패닉한다.

06 · X 데스크톱

로그인하면 커널이 죽던 문제: EMS cgroup 배열 넘침

구성

features/desktop: Xorg(fbdev, /dev/fb0), Openbox, LXTerminal, 나눔 글꼴, Firefox ESR, mpv. 278개 패키지, 설치 뒤 901 MB.

패닉의 사슬

  1. desktop 패키지가 libpam-systemd를 들인다
  2. 로그인마다 user@UID.service가 cpu 컨트롤러를 위임받는다
  3. cpu cgroup이 9개를 넘는다
  4. vendor ems.ko가 9칸 배열 밖을 써서 UBSAN BRK 0x5512(freqboost_can_attach)

막는 법: 부트 명령줄 cgroup_disable=cpu(boot-nocpu), 또는 user@.service에 Delegate=pids memory.

CPU로 그리는 X 데스크톱(fbdev). YouTube는 480p가 제 속도였다. GPU X는 08장

교훈: 패키지를 apt로 들이기 전에 apt-get -s install …로 libpam-systemd가 끼는지 본다.

07 · 최적화 2

오래 켜 둘 수 있게: 로그, 복구, 성능 상태

로그 줄이기 (11.32)

journal이 60초에 7,816줄(초당 130줄)이라 1시간 50분이면 기록이 밀려났다. 카메라 bypass의 정상 동작 메시지와 워치독 keepalive를 조용히 했다.

7,816 → 38줄 / 60초

자동 복구

  • soft lockup → 패닉 → 5초 뒤 리셋 → 워치독 → fastboot → 정상 이미지
  • Wi-Fi 펌웨어 패닉 → 6초 안에 재연결
  • DVS live가 CRC 폭주 때 스스로 다시 시작

성능 상태 고정 (데스크톱)

e850-x가 GPU 1001 MHz, MIF·INT를 최대로 고정하고 GPU X를 띄운다. e850-x stop이 푼다. GPU DVFS는 kbase가 사용률을 모으지 않아 377 MHz에 머물기 때문이다.

메모리

zram 1.8 GB. 보드 /tmp는 부팅 때 비워지므로 남길 파일은 /var/tmp에 둔다.

08 · GPU 1

커널 드라이버는 있는데 GL이 없다: Mesa panfrost + kbase shim

앱 (GLES 3.1)→Mesa panfrost
오픈소스→drm-shim (LD_PRELOAD)
panfrost ioctl → kbase ioctl→/dev/mali0
vendor mali_kbase r38p1→Mali-G52

출발점

mali_kbase는 이미 올라와 있었다. Mali 사용자 공간 라이브러리는 Android(bionic)용뿐이라 Debian에서 쓸 GL이 없었다.

방법

Icecream95의 kbase-g52 브랜치(Mesa 22.2-devel)에 패치. 커널을 바꾸지 않고, root도 필요 없다. 빌드는 tools/gpu/.

맞춘 것

GPU 노드에 dma-coherent가 없다 → 큰 이미지 BO만 CPU 캐시로 잡고 shim이 clean/invalidate. 이 GPU에서 결과가 틀리는 AFBC와 IDVS는 끈다.

결과: 보드3에서 일반 사용자로 화면 없이 GLES 3.1이 돈다. 그리기 검사 ~/gpu/run-test.sh(gles-test, gles-subtex, gles-inst) 115 fps.

08 · GPU 2

그린 것을 화면에 보이기: 세 단계

① 읽어서 X 창에

gles-x11: GPU 결과를 읽어 X 창에 보낸다. 720p 42~54 fps. 복사가 있다.

→

② fb0에 바로

modules/e850-fbbuf가 fb0 버퍼를 dma-buf로 꺼내 준다. GPU가 그 메모리에 그리고 FBIOPAN_DISPLAY로 바꾼다. 사용자 공간 S3CFB_WIN_CONFIG는 fb0 메모리를 풀어 버리니 쓰지 않는다.

→

③ 작은 KMS 장치

modules/e850-kms: fbdev DECON 위에 /dev/dri/card0(이름 exynos). 페이지 전환은 fb0 pan으로, 30 fps가 상한.

GPU X (vt8의 두 번째 X)

Xorg modesetting + glamor + DRI3, Mesa는 panfrost,kmsro. 클라이언트는 kenv로 같은 Mesa 환경에서. Firefox가 하드웨어 WebRender로 돈다.

dpu는 DRM이 아니다

vendor 디스플레이는 fbdev 드라이버뿐이고 메인라인 exynos_drm은 Exynos850 DECON을 모른다. 그래서 전체 DRM 드라이버 대신 X가 필요로 하는 만큼만 만들었다.

08 · GPU 3

성능과 그리기 오류: 원인을 재고 고친 것

증상원인 (잰 것)고친 것결과
YouTube 720p60이 GPU X에서 39~46 fps (CPU 경로 58.3)Renderer 스레드가 CPU 일 18 ms와 GPU 대기 8 ms를 번갈아 함. shim이 동기 제출, 제출마다 모든 BO clean비동기 제출(atom마다 앞 atom에 ORDER 의존), Mesa가 CPU 쓰기를 알린 BO만 clean58~60 fps
글자 빠짐, 타일 깨짐꼭짓점 셰이더가 쓴 위치가 셰이더 코어 LS 캐시에 남아 타일러가 옛 값을 읽음꼭짓점 job과 타일러 job 사이에 LS clean 캐시 flush job시험 프로그램 PASS, 글자 정상
GPU가 377 MHz에 머묾kbase가 사용률을 모으지 않아 DVFS가 안 올림e850-x가 1001 MHz 고정데스크톱 동안만

재는 도구

/proc/PID/task/TID/syscall을 2 ms마다 읽는 표본기로 스레드가 어디서 기다리는지 봤다. PAN_KBASE_STATS=1이면 5초마다 제출·대기·clean 통계.

끄는 스위치

PAN_KBASE_SYNC=1(동기), PAN_E850_FLUSH=0(LS flush 끔), PAN_KBASE_UNCACHED=1(CPU 캐시 안 씀). 비교 시험을 바로 할 수 있게 남겼다.
